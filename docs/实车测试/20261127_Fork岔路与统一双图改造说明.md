# 2026-11-27 Fork（岔路）问题诊断与双图统一系统改造说明

## 一、现场视频分析与两个问题的直接根因

### 问题 1：Fork 岔路选错数字（该走 `8` 却拐进 `6`）
从第 1 段实拍视频观察到，小车在黄线后同时接近左侧低分圆标 `6` 与右侧高分圆标 `8`：
1. **单侧先确认抢先触发**：只要左/右两个空间槽里有一侧先攒够 `min_votes=2` 帧，旧逻辑会立刻发出转向指令；当右侧 `8` 恰好晚 `1~2` 帧进入触发窗或反光掉帧时，左侧 `6` 直接抢先锁定进入岔口。
2. **缺少跨帧空间槽记忆（Slot Memory）**：高处灯光照在亮面赛道贴纸上会导致 `8` 偶发掉帧 `2~5` 帧，旧逻辑只看最近 `4` 帧滑动窗口，一旦 `8` 滑出窗口，`6` 就会胜出。
3. **缺少单帧高置信否决（Global Max Veto）**：即便 `8` 在当下这一帧已经以高置信度出现（只有 1 票），旧逻辑依然按已满 2 票的 `6` 提前发令。

**解决方案**（[`digit_decision_logic.hpp`](../../src/line_follow_ws/src/line_follower/include/line_follower/digit_decision_logic.hpp)）：
- 新增 5 个默认关闭、按 YAML 启用的参数（不破坏原环岛任何已有配置）：
  - `pair_hold_sec: 0.45` & `pair_release_y: 0.68`：只有一个空间槽确认且目标尚未落到近距释放线 `y>=0.68` 时，主动等待成对数字出现，不再被先到的低分数字抢跑；直道单数字到达 `y=0.68` 后立刻释放，无感延迟。
  - `slot_memory_sec: 0.80`：跨帧记忆左右两个已确认槽位的最高分结果，短暂反光掉帧 `8` 依然能压住 `6`。
  - `enforce_global_max_veto: true` & `max_veto_min_conf: 0.60`：只要滑动窗口里出现比当前胜者更大的高置信未确认候选，就继续短暂等待其补足票数。

### 问题 2：画框 `┤` 丁字汇合口处丢线 / 撞黑墙
从第 2 段实拍视频及地图画框位置可见，抄近道右拐进横杆后垂直撞向右侧黑边 `┤` 字墙（画框处）：
1. **斜入角 + 角落红色禁行区打断平墙判据**：画框右上/右下常贴近弯角或红禁行区；原先依赖 `full_rows >= 65` 与统一整行顶边黑度要求斜率接近水平，斜切进框时顶边检测直接失效。
2. **红色并集未连通**：禁行区空心红框会在 `road_mask` 横杆角上抠出黑色缺口，削弱横向宽度判据并诱发反向避障抽动。
3. **缺“贴墙即失线”救护机制（Anti-LOST Rescue）**：一但撞到框边导致前视找不到连续白道（`!line_detected`），原分支会直接走进 `LOST` 低速直冲黑线。

**解决方案**（[`tjunction_merge_detector.hpp`](../../src/line_follow_ws/src/line_follower/include/line_follower/tjunction_merge_detector.hpp)）：
- 实现**与斜入角度无关、抗红区遮挡的 `┤` 丁字并线状态机**：
  - 将 `binary_mask` 与膨胀后的红色区域做底边 10 行连通域过滤（`connectedComponents`），消除禁行区缺口并彻底屏蔽赛道外反光。
  - 改为**逐列向上回溯墙顶边缘**计算 `top_wall_dark_ratio`，在斜切 ±25° 进入画框时仍保持高对比度检测。
  - `line_follower_node` 在 `enable_tjunction_merge: true` 且第 2 条黄线后里程门控（`tjunction_min_arm_dist: 0.32m`）解锁后，即使当帧已经 **`!line_detected`** 也照常送入状态机：一旦撞墙丢线或前方只剩横杆底边（`rescue_upper_road_ratio <= 0.12`），**0 延迟触发右并线救护转向**；转向 ≥ `0.85s` 后一旦前方直道重开即闭环交回 PD 巡线。

## 二、两张地图统一架构说明（单套编译产物，纯 YAML 切换）

现在 `main` 分支的 C++ 三节点（[`cmd_mux_node.cpp`](../../src/line_follow_ws/src/line_follower/src/cmd_mux_node.cpp)、[`detection_turn_controller.cpp`](../../src/line_follow_ws/src/line_follower/src/detection_turn_controller.cpp)、[`line_follower_node.cpp`](../../src/line_follow_ws/src/line_follower/src/line_follower_node.cpp)）已经把两张地图的全部能力合为一体，**无需切换分支或维护两套代码**：
- **4 级统一多路复用**：`stop (/cmd_vel_stop) > avoid (/cmd_vel_avoid) > high (/cmd_vel_detection) > low (/cmd_vel_follower)`，统一兼顾黄线刹停、丁字并线/红障避让、YOLO 数字转向与常规巡线。
- **环岛图（Ring）**：使用 [ring_opt4_20261127](../../src/line_follow_ws/src/line_follower/config/parameter_presets/ring_opt4_20261127) 参数，`enable_tjunction_merge: false`，开启 `red_avoid_max_lat_accel` 与弯道预瞄。
- **岔路图（Fork）**：使用 [fork_opt4_20261127](../../src/line_follow_ws/src/line_follower/config/parameter_presets/fork_opt4_20261127) 参数，打开 `enable_tjunction_merge: true` 与 `enable_robust_digit_decision: true`。

## 三、连车后编译与启动命令（统一工程目录）

下次小车开机连上热点后，将本仓库 `src/line_follow_ws/src/line_follower` 同步到车端并执行一次编译即可同时服务两张地图：

```bash
# 车端编译（ROS 2 Humble / TROS）
cd <车端工作区>/src/line_follow_ws
source /opt/tros/humble/setup.bash
colcon build --packages-select line_follower

# 启动 Fork 岔路图首测（建议配合 record_bag.sh 录包）
bash src/scripts/start_line_following.sh --map fork --params YOLO_FORK_OPT4_S030_BASE.yaml --yolo

# 启动 Ring 环岛图测试
bash src/scripts/start_line_following.sh --map ring --params YOLO_RING_OPT4_S060_LATCAP.yaml --yolo
```
